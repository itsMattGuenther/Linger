# Linger 0.3.5

Typing and scrolling keep up on Linux again, replies read clearly, long rooms
stay light, and reactions come out as a trial. This is an app-only release: the
server is unchanged since 0.3.4, so hosts do not need to update.

## Messaging

- **Reactions are out, as a trial.** Messages show no reactions and the message
  menu no longer offers one. Answer by replying or saying something; the emoji
  button in the message box still puts emoji into what you type. The server
  keeps reactions, so older apps still show them and bringing them back loses
  nothing (#168; SPEC §4.8 and `docs/decisions.md` changed).
- A reply's quote sits against the reply it belongs to, a thin bracket joins
  the two, and a reply that follows another message from the same person gets
  space above it. Two replies in a row no longer look like one message (#181).
- Scrolling does a fraction of the work it did: only messages coming into view
  are drawn, and times are no longer re-formatted on every frame. Mouse-wheel
  scrolling in a 10,000-message room no longer drops frames in testing (#170).
- Rooms let go of history far from the screen. Scroll a long way back and the
  header offers **back to the newest**, now on the room name's line; scrolling
  down brings everything back with nothing missing. Rooms you leave keep only
  their newest messages (#173).

## Linux desktop

- **Typing and scrolling no longer run a beat behind the keys.** 0.3.3 and 0.3.4
  turned off WebKit's GPU display path on every Linux computer, which delays
  every frame. It now stays on under native Wayland and off under X11 (#169).
- If a launch that tries the GPU path stops before drawing anything, the next
  launch notices and keeps it off on that computer. Delete
  `~/.local/state/linger/gbm-off` to try again. Setting
  `WEBKIT_DMABUF_RENDERER_DISABLE_GBM` yourself still wins.
- The AppImage menu entry no longer saves Linger's own graphics defaults, which
  is what kept the old setting on after updates. The first launch after
  updating may still feel slow; the next one will not.

## Rail and settings

- The Media and Search icons are centered on their labels, and both icons are
  redrawn to sit in the middle of their space (#172).
- The account footer shows your name and Settings on one line, without "you"
  under the name (#171).
- When an update is waiting, Settings shows a **what's new** button that opens
  the release notes in your browser, instead of printing them in full (#174).

## Install or update

Use the in-app update action. Windows users should keep the same installer
format (`.exe` or `.msi`) when upgrading. Linux packages are available as
`.AppImage`, `.deb` and `.rpm`. Windows installers are updater-signed, not
Authenticode-signed; SmartScreen may still warn about an unfamiliar app.

Server image: `ghcr.io/itsmattguenther/linger:0.3.5` (amd64 and arm64) is the
same server as 0.3.4. No protocol changes; older apps and servers keep working.

## Checks on installed clients

Record OS, package type, previous/new version and interface size with any failure.
Use synthetic messages and avoid private conversations in screenshots.

1. Update from 0.3.4. On Omarchy or another Wayland desktop, launch twice from
   the application menu: by the second launch, fast typing in the message box
   and fast scrolling keep up. `~/.local/share/applications/com.linger.desktop.desktop`
   no longer contains `WEBKIT_DMABUF_RENDERER_DISABLE_GBM=1`.
2. Open a room with old reactions: none show, and the message menu has reply,
   edit and delete only. Reply twice in a row with an emoji: each quote sits with
   its own reply.
3. Scroll far back in a long room, stop, keep reading: nothing jumps. Use **back
   to the newest**, then scroll back down from far back instead: no missing or
   doubled messages.
4. Check the rail at a large interface size: Media and Search icons level with
   their labels, and the footer one line tall.
5. With 0.3.5 installed, a future update's **what's new** opens the release page
   in your browser.

Physical listening, real graphics on affected hardware, and separate-machine/
network release checks remain open until their stated evidence exists. Issues
#81, #101 and #147 remain deferred. M12 remains the current milestone.
